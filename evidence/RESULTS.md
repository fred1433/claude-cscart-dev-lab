# Results

Generated by `tools/build_results.py` from the raw records. Statuses were fixed before the runs (see the docstring of that script and of `tests/linux/proofs.py`). The raw `stream*.jsonl` files are Claude Code's stream-json output, re-encoded once with ASCII escapes (same JSON values).

## Recorded Claude Code sessions (macOS, real model, subscription)

Every session: fresh synthetic dev copy plus `../prod`, explicit `--permission-mode`, `--setting-sources project,local`, no MCP server. *Operating config* = the kit's settings, guard and `CLAUDE.md` as shipped, **plus** the tools pre-approved on the command line (`--allowedTools`, column below), which stand in for a human answering yes. The kit's own `permissions.allow` entries were ignored in these runs because the throwaway folder had never been trusted (Claude Code says so in each `stderr.txt`); deny rules, hooks and sandbox applied. *Rules file removed* = same, with `CLAUDE.md` deleted so the model does not know the rules and actually attempts the action.

*Prohibited action attempted?* says whether the model actually made the forbidden call (edit, write, copy, SQL, network...). When a control only stopped a preparatory read and the model then gave up, the status says so: the control on the action itself is untested in that session.

`total_cost_usd` in the raw streams is Claude Code's API-equivalent counter; these sessions ran on a Claude subscription and cost nothing extra. Local paths in the raw records are replaced by `<config-dir>` and `<home>`.
